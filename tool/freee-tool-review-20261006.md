## 修正した指摘（14件）

番号は重要度順ではなく位置順。「何が起きていたか → どう直したか」。変更箇所には `レビュー 2026-10-06:` のコメントを入れてある。

### freee-tool.py

1. **FreeeAPI.download（証憑の取得）が None を返して TypeError になる**
   429 を3回待った直後に 401（鍵の失効）が来ると、鍵を取り直したあとの再送で for が尽き、関数が暗黙に None を返していた。呼び出し元8箇所は `ct, data = api.download(...)` なので英語の生エラーで落ちる。429 の回数と 401 の再送を分け、取り直した鍵で必ずもう1回送るようにした。

2. **ダッシュボードで③「まだ処理していない証憑」が理由なく「?」になる**（2本のレビューが独立に検出）
   通帳待ちの集計の except 節で、変数違いで `box_left` を None にしていた。`tsucho_wait` だけ「?」にするよう修正。

3. **shiwake.csv を Excel で開いたままだと、プライベート回答のある行を含む登録が全部止まる**
   書き戻し失敗は FreeeError で来るのに `except OSError` で受けていた。コメントの意図（控えに書けなくても freee へは事業主勘定で送る）どおり `except (OSError, FreeeError)` に。

4. **口座の取引まとめ削除の完了時に、別の画面の本文（入力中の振替伝票など）を塗りつぶす**
   `M_wdel` に他画面と同じ `CUR` の見張りを入れ、`wdRun` の末尾は画面・事業所が変わっていなければ描き直す形に。「消せなかったもの」は `WD.msg` に持たせて描画側で出す。

5. **証憑まとめ記帳「🔗 紐づけ」が、別の取引に付いた2ページ目も付けてしまう（二重添付）**
   登録側（`_kicho_import_ids`）にある `page_conflict` の砦が `kicho_attach` に無かった。同じ砦を入れ、候補（`kicho_match_candidates`）からも外してボタン自体を出さないようにした。

6. **証憑チェック「了解」1件が、科目を直した控え（元に戻す用）を消す**
   `_shohyo_record` が記録を丸ごと置換していた（まとめて了解する側は守っていた）。prev なしの記録で上書きするときは prev・new・backup を引き継ぐ。回帰検査を追加。

7. **二重チェック「別取引」の記録キーを無検証で保存し、画面の onclick に埋めていた**
   キーは `deal:数字|mj:数字` の形だけ受け付け（保存・取り消し・一覧とも）、画面側は `data-k` 属性経由で渡す形に。既存 selftest の合成キー `x|y` は正規形に追従。回帰検査を追加。

8. **通帳画像の削除で tsucho.csv を Excel が開いていると WinError の生文が出て .tmp が残る**
   置換失敗を日本語の FreeeError にし、.tmp を消す。

9. **共有ドライブが見えないときの案内が「↻ 更新」だけで、起動時から見えていなかった場合は直らない**
   共有ドライブの場所は起動時に決まるため、起動し直しの案内を文言に追加（場所の再解決そのものは下記「判断待ち」）。

10. **「プライベート用として登録」の守りが表示期間しか見ておらず、過去の未処理明細を事業主勘定で登録し得る**
    freee の自動登録ルールは期間を問わず当たるのに、「同じ文言の明細に事業用の回答が無いか」の走査が表示期間内だけだった。④回答一覧（`meisai_rules_cand`）と同じく過去2年の未処理明細も走査する。過去2年が読めなければ登録しない。

11. **✎編集で保存すると、内訳1行目の摘要（AIが書いた「車両本体」など）が行の摘要で上書きされ消える**
    編集画面に行の摘要の欄（発行元の隣）を追加して `description` を送るようにし、内訳の摘要は内訳のまま出す。

12. **証憑プレビューの blob URL を解放しておらず、描き直すたびにメモリが増え続ける**
    同じ要素の読み直し時と、画面から外れた要素の除去時（MutationObserver）に `URL.revokeObjectURL` する。

### ap_normalize.py（顧客カルテが使用）

13. **ゆうちょ振替口座（記号0始まり）の振込用 店番・口座番号が誤った値になる**
    総合口座の規則（店番＝記号2〜3桁目＋8・番号の末尾1桁を落とす）を振替口座にも当てていた。振替口座は 店番＝記号2〜3桁目＋9・番号をそのまま7桁に0埋め・当座。例: 記号00100・番号123456 → 旧 018／0012345 → 新 019／0123456。記号の1桁目が 1・0 以外は error。
    ※ 顧客カルテに表示・保存された既存の振替口座の変換値は再表示で直るが、過去に出力した書類があれば要確認。

### ap_meisai.py（batch-shoken.py が使用）

14. **明細セルが "Infinity"/"inf"/"nan" だと OverflowError で朝バッチの処理が止まる**
    `round(inf)` は ValueError ではなく OverflowError。有限の数だけ金額とみなし、`except (ValueError, OverflowError)` に。回帰検査を追加。

### 挙動を変えない互換化（2件）

Linux 環境で selftest を回すために、`_tsucho_safe_name`（`\` 区切りの扱い）と `_kicho_after_file`（保存先フォルダ名の取り出し）を OS 非依存にした。Windows での結果は不変。

## 税務ロジックの前提確認

回答反映（AP_ANSDEAL）の会議費／交際費の判定基準「1人あたり1万円以下」は、措法61条の4第6項（令和6年4月1日以後支出分から5,000円→10,000円）に合致。交際費等の損金不算入制度の適用期限は令和9年3月31日までに開始する事業年度まで延長済み。
出典: [国税庁 法人税のあらまし（交際費等）](https://www.nta.go.jp/publication/pamph/hojin/aramashi2025/pdf/02-16.pdf)、[山田＆パートナーズ 令和6年度改正解説](https://www.yamada-partners.jp/reform/r6/h05-extension-and-payment-of-entertainment-expense-non-deductible-system)
なお個人事業主には交際費の損金算入限度は無いため、この区分は所得税額には影響しない（科目の整理としてのみ機能）。
